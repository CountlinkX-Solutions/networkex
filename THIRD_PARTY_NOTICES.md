## (a) Code in the Hex package

### spaghetti

Networkex is a port of [spaghetti](https://github.com/pysal/spaghetti), PySAL's library for
spatial analysis on networks, and follows its behaviour and the published literature it cites
(Okabe and Sugihara, 2012, *Spatial Analysis Along Networks*). To reproduce spaghetti's results
exactly, portions of its source code (spaghetti 1.7.6) were translated into Rust and Elixir. These
functions are derived from it; each carries a comment that names its spaghetti source:

| Networkex | spaghetti 1.7.6 |
|---|---|
| `native/networkex_core/src/network.rs`: `round_vertex` | `Network._round_sig` (`spaghetti/network.py`) |
| `native/networkex_core/src/network.rs`: `build_with` | the vertex and arc loop of `Network._extractnetwork` |
| `native/networkex_core/src/network.rs`: `components` | the component attributes of `Network.identify_components` (the labelling itself is a union-find) |
| `native/networkex_core/src/network.rs`: `extract_graph` | `Network.extractgraph`, `_yield_napts`, `_evaluate_napts`, `_yieldneighbor` |
| `native/networkex_core/src/distances.rs`: `point_link` | `squared_distance_point_link` (`spaghetti/util.py`) |
| `native/networkex_core/src/distances.rs`: `all_neighbor_distances` | `Network.allneighbordistances` |
| `native/networkex_core/src/distances.rs`: `shortest_paths` | `Network.allneighbordistances` with `gen_tree=True` |
| `native/networkex_core/src/distances.rs`: `route`, `drop_joints` | `Network.shortest_paths` |
| `native/networkex_core/src/kfunction.rs`: `point_along` | `Network._newpoint_coords` |
| `native/networkex_core/src/kfunction.rs`: `simulate` | `Network.simulate_observations` |
| `native/networkex_core/src/kfunction.rs`: `curve`, `global_auto_k` | `global_auto_k`, `GlobalAutoK.computeobserved` and `computepermutations`, `FuncBase.setbounds` and `computeenvelope` (`spaghetti/analysis.py`) |
| `native/networkex_core/src/utilities.rs`: `split_arcs` | `Network.split_arcs` |
| `lib/networkex/network.ex`: `regular_lattice/3`, `chains/5` | `regular_lattice` (`spaghetti/network.py`) and `build_chains` (`spaghetti/util.py`) |

The rest of Networkex reimplements spaghetti's documented behaviour, with its own algorithms and
data structures, and is checked against spaghetti's outputs. The test fixtures under
`test/reference/fixtures` are generated by running spaghetti and libpysal (dev-time only, see
`test/reference/README.md`); they contain numerical outputs, not code, and the fixtures computed
on the geodanet data are derived from that data (see (c)). The fixtures are not part of the Hex
package.

The `networkex_core` code, including these functions, is also compiled into the precompiled NIF
libraries.

### CPython (networkex_core)

`native/networkex_core/src/hypot.rs` ports the algorithm of CPython's `math.hypot` (`vector_norm`
in `Modules/mathmodule.c`, as in CPython 3.13), so segment lengths match libpysal's bit for bit.
It is part of the Hex package and of the precompiled NIF libraries.

```text
Copyright (c) 2001-2024 Python Software Foundation; All Rights Reserved
```

Summary of the changes made to CPython's code (clause 3 of the license below):

- translated from C to Rust;
- reduced to two arguments, `math.hypot(x, y)`: the loop over a vector of any length and the
  shortcut for fewer than two values are gone, and the infinity and NaN checks of `vector_norm`
  run on the two values before the norm;
- `frexp` and `ldexp` are replaced by exact operations on the bits of the IEEE 754 double;
- the error-free product always uses a fused multiply-add (`f64::mul_add`); CPython's
  Veltkamp-Dekker alternative for platforms without a reliable fma is not ported;
- the rescaling of subnormal inputs by `DBL_MIN` (`f64::MIN_POSITIVE`) and every other
  arithmetic step are kept in CPython's order, so results are bit for bit those of `math.hypot`;
- unit tests and a comparison with CPython's results (`test/reference/fixtures/hypot`) are added.

### Regenerating this list

Update the table whenever `Cargo.lock` changes, before a release is tagged. Cargo prints the
linked crates and their declared licenses for each target (no other tool is needed):

```sh
for target in aarch64-apple-darwin x86_64-apple-darwin aarch64-unknown-linux-gnu \
              x86_64-unknown-linux-gnu x86_64-unknown-linux-musl x86_64-pc-windows-msvc; do
  echo "== $target"
  cargo tree -p networkex_native -e normal,no-proc-macro --target "$target" \
    --prefix none --format "{p} | {l}" --locked | sort -u
done
```

Copyright notices come from each crate's license files, which Cargo unpacks under
`~/.cargo/registry/src/` (`cargo metadata --locked --format-version 1` gives each crate's
`manifest_path`).

## (c) Data in the repository only

None of the files below is part of the Hex package: they are read by the fixture generators and
the notebooks of the source repository.

### libpysal example data

These files are byte-for-byte copies of libpysal 4.15.1 example datasets
(<https://github.com/pysal/libpysal>, `libpysal/examples`):

- `test/reference/data` and `notebooks/data/geodanet`: the `geodanet` dataset ("Datasets from
  GeoDaNet for network analysis"), streets, crimes and schools of Tempe, Arizona, as used in the
  spaghetti tutorials;
- `notebooks/data/snow`: the `snow_maps` dataset ("Public water pumps and Cholera deaths in
  London 1854 (John Snow's Cholera Map)"). libpysal cites Snow, J. (1849), *On the Mode of
  Communication of Cholera*, and names no digitiser.

Each directory holds a subset of the upstream directory. Left out are the upstream `README.md`
files (their content is summarised here and in each directory's README), the spatial index files
(`.sbn` and `.sbx`) of every layer, and `crimes.shp.xml` of `geodanet`, an unfilled metadata
template whose origin and constraint fields hold only placeholders (for example "REQUIRED: The
name of an organization or individual that developed the data set."). The `streets` layer of
`geodanet` and the `snow_maps` layers ship no metadata file upstream.
